# Contributing to IntentChord

IntentChord welcomes proposals that improve its correctness, testing, usability and maintainability while preserving explicit owner authority and evidence provenance.

## Before contributing

- Read the [license](LICENSE) and [CLA v1.0](CLA.md). The PolyForm Noncommercial license controls your use of the released code. The CLA is a **separate agreement for contributions merged into the official project**.
- You do **not** need a CLA merely to read, clone, fork or test the released code within its license.
- Never submit credentials, private logs, customer information, employer-owned work without authorization, or third-party content without compatible permissions.
- Use an isolated local development setup. Do not run migrations against production or other people's data.

## Issues and changes

1. Describe the issue or proposed improvement and the affected feature.
2. Keep each change narrowly scoped and disclose impact on scope confirmation, source authority, AI runs, evidence and owner approval.
3. Include appropriate tests and explain untested areas. Do not claim production acceptance from a passing unit test.
4. Disclose new third-party dependencies, reused assets and material licensing/provenance uncertainty, including AI-assisted code when relevant.
5. Submit a Pull Request with a summary and validation evidence. The Project Owner or delegated maintainers decide whether it is merged.

## Contributor rights and agreement

Contributors keep copyright in their original submissions. For official inclusion, the appropriate rightsholder must affirmatively accept [CLA v1.0](CLA.md). A maintainer will arrange the private signature/acceptance process and record its version before merge; **opening a Pull Request does not automatically sign the CLA**.

The CLA permits IntentChord to use and commercially relicense covered contributions while leaving the contributor's original ownership intact. Payment, revenue shares and paid work are **not automatic** and require individually negotiated written agreements.

Signing is tied to actual contributors; it is not a prerequisite to publishing the source repository. The project may reject a submission that cannot be legally included.

## Responsible security reporting

Do not put secrets, vulnerabilities with exploit details or credentials in public issues. Follow [SECURITY.md](SECURITY.md) for private reporting options.
